# Phase 3C：目标策略、多目标协调与配置界面

## 1. 阶段目标

本阶段恢复 1.12.2 的完整目标决策链，并用 1.21.1 的服务端权威模型实现：

- 敌对、被动/中立、玩家三个目标类别开关；
- 所有者、本地/全局信任、队伍盟友和受信玩家宠物保护；
- 每种炮塔各自的五维默认优先级；
- multi-target 模式下，相邻炮塔头不重复选择同一目标；
- 玩家进入警告范围后的消息与声音，以及有界冷却；
- 底座菜单的 `ContainerData` 同步和可实际操作的目标配置 UI；
- C2S 只表达操作意图，服务端再次验证菜单、距离、权限、命令和值域。

## 2. 旧版语义与现代化决策

### 2.1 目标分类

- `Enemy` 对应旧版 hostile/mob；
- 其他 `Mob` 对应旧版 passive/neutral；
- 玩家只有在玩家目标开关开启、不是所有者或受信玩家、不是创造/旁观者且允许 PvP 时才合法；
- `TamableAnimal` 的主人为所有者或受信玩家时永不成为目标；
- 所有者在线时，`isAlliedTo(owner)` 为真的实体受保护；
- 非 `Mob`、非玩家的普通 `LivingEntity` 默认不进入候选集；
- 使用 `openmodularturrets:target_blacklist` 实体类型标签提供数据包可扩展黑名单。

旧版对驯服马采用“一律保护”，现代版继续采取保守策略：具有所有者且已驯服的实体受所有者/信任关系保护，不凭空攻击来源不明的驯服宠物。

### 2.2 距离与视线

- 搜索盒仍采用底座配置射程；
- 最终距离判定采用炮塔头中心到目标的欧氏距离；
- 每次保留/获取目标都重新验证存活、类别、权限、距离与方块碰撞视线；
- 扫描保持每 10 tick、按方块位置错峰，避免同 tick 扫描尖峰。

### 2.3 五维优先级

旧版顺序为：

1. 最大生命；
2. 已损失生命；
3. 距离；
4. 护甲；
5. 玩家。

默认权重继续由炮塔种类持有，并迁移旧类中的默认数组。旧版把五项整数相乘，存在零权重吞掉其他维度、负数翻转和整数溢出问题。本移植采用归一化加权和：

`score = Σ(normalizedMetric * weight)`

权重保留正负方向；分数更高者优先。相同分数按距离、实体 ID 决定，保证可重复。Phase 3C 先恢复每类炮塔默认策略；逐炮塔自定义编辑器在炮塔详情 UI 阶段实现，持久化位置仍预留在炮塔头。

### 2.4 Multi-target

- 默认关闭，与旧版一致；
- 关闭时多个炮塔可以集中攻击同一目标；
- 开启时，获取新目标的炮塔排除已被同一底座其他相邻炮塔锁定的实体；
- 已有目标不会因为另一个炮塔后来锁定而被强制清除，避免抖动；
- 只扫描底座六个相邻位置，预算固定为 6。

### 2.5 玩家警告

- 仅当玩家目标开关开启且底座 active 时运行；
- 警告范围为当前攻击范围额外 5 格；
- 只警告实际不受所有者/信任保护、非创造、非旁观的玩家；
- 同一底座对同一 UUID 的冷却为 12,000 ticks；
- 冷却表只在内存中保存、按需清理并限制为 128 项，不写入世界 NBT；
- 使用已有 warning 音效和可翻译红色系统消息。

## 3. 状态、持久化与同步

### 3.1 BlockEntity

底座新增持久化字段：

- `multi_targeting`

炮塔默认优先级由 `TurretDefinition` 决定，不重复写入 NBT。未来用户覆盖值写入炮塔头自己的版本化数据。

### 3.2 Data Component

Memory Card profile 升级到 schema 2，新增 `multi_targeting`。Codec 必须能读取 schema 1 并为该字段补 `false`，写出统一使用 schema 2。组件只保存可复制的配置，不保存所有者、信任表、能量、计数器或临时警告冷却。

### 3.3 菜单数据

`TurretBaseMenu` 使用 `ContainerData` 同步：

- active；
- configured range；
- maximum range；
- 三个目标类别位标志；
- multi-target；
- 当前访问等级。

客户端 screen 只能读取 menu data，不读取客户端 BlockEntity 镜像作为权威状态。

### 3.4 网络

继续使用现有 `BaseCommandPayload`，不新增冗余 S2C 状态包。命令 ID 由稳定枚举管理：

- set active；
- set range；
- set target flags；
- set multi-target。

服务端拒绝未知命令、越界范围、无匹配菜单、超过 8 格、没有 `USE` 权限或超过速率限制的请求。

4. 增加有界玩家警告冷却；
5. 升级 Memory Card schema；
6. 增加菜单 `ContainerData`、安全命令枚举和目标配置 screen；
7. 添加纯规则测试与 GameTest；
8. 运行合同、编译/静态、DataGen/资源、专服、GameTest 和 fast pipeline。
